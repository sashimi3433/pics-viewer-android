# 青延長リクエストのプロトコル調査（実地キャプチャ手順）

高度化PICS の受信（アドバタイズ）は解析済みですが、**青延長要求の送信方法は公開されていません**。
公式アプリ「信GO!」が実際に送っているパケットを1回キャプチャできれば、同じ要求を実装できます。

## 前提

- 公式アプリは、交差点のサービス範囲内（登録座標から Radius 20〜30m 程度）にいる場合のみ
  延長要求を受け付けるようです（それ以外では案内自体が出ない）。
- 延長に対応していない交差点では、長押ししても要求できません。

## 方法A: Android の HCI スヌープログ（BLE を見る・推奨）

1. 端末の開発者向けオプション → 「Bluetooth HCI スヌープログを有効にする」を ON
2. Bluetooth を OFF → ON（設定を反映）
3. 交差点で「信GO!」を起動し、青延長を実行（画面長押し）
4. PC と USB 接続して取得:

   ```sh
   adb bugreport ~/pics-capture.zip
   unzip -o ~/pics-capture.zip -d ~/pics-capture
   find ~/pics-capture -name "btsnoop_hci.log"
   ```

5. `btsnoop_hci.log` を送ってもらえれば、Wireshark で
   - GATT 接続か / アドバタイズ送信か
   - Company ID `0x01CE` の新しいメッセージタイプ（0x03 など）
   - 書き込み先のキャラクタリスティック UUID とペイロード
   を特定します。

## 方法B: iPhone + mitmproxy（HTTP 経路を見る）

1. Mac で `mitmproxy` を起動し、iPhone の Wi-Fi プロキシに指定
2. `mitm.it` から CA 証明書をインストールして信頼
3. 信GO! で延長を実行
4. `www.j-signal.jp` への POST があれば、URL とボディを共有

（BLE は iPhone 単体では取りにくいので、可能なら方法Aで）

## こちらの実装手順（キャプチャ後）

1. パケットの再現 → アプリに「延長要求」を追加（長押しUI）
2. 送信前に、対象交差点ID・チャンネル・現在の灯色を再確認
3. 公式アプリと同じ条件（交差点内・青の間のみ）でガード
4. 実機で「要求を受け付けました」相当の応答が返るか確認

## 注意

- 送信機能は、公式アプリと同じ要求を再現する形に限定します（独自の連打・連続延長はしない）。
- 交差点の制御に影響するため、テストは必ず現地で、歩行者に配慮して行うこと。
